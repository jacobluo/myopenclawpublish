ENGINEERING PRACTICES
  • ① Report-only 起步 — 第一个 loop 不自动改代码，先跑一周看信号质量
  • ② 规则写进 Skill — Loop prompt 要短，项目规则放 skill 里
  • ③ Worktree 隔离 — 并行 Agent 用不同 checkout，避免互相覆盖
  • ④ Maker ≠ Checker — 写代码的 Agent 不能给自己判"已完成"
  • ⑤ State 是脊柱 — 每次运行先读状态，结束时写状态
  • ⑥ 预算写进系统 — 高频 loop 必须有 early exit、上限和最大重试
ANTI-PATTERNS
  • Prompt Cron — 只把长 prompt 放进定时器，没有 state/预算/验证
  • 自我验收 — 同一个 Agent 写代码并宣布完成
  • 无限修复循环 — 同一 PR 反复修改，越修越乱
  • 通知疲劳 — 每次运行都 ping 人，导致忽略真正信号
  • 理解债务 — Loop 产出越来越多，人越来越不理解系统
