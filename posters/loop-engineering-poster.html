Loop Engineering

把 Agent 从一次对话，变成可维护、可观察、可回放的任务闭环。
Core thesis

Loop 不是更长的 prompt；它是带模型能力的任务运行时。

02

中
对比
关系

Harness

单次执行的可靠性

工具、沙箱、上下文、权限、hook、测试命令和输出格式。目标是让一次 Agent run 不迷路、不误操作。

Loop

跨时间的持续运营

调度、状态、预算、验证、通知、交接和长期改进。目标是让系统知道如何继续，也知道何时停止。

Relationship

不是二选一

Environment 决定能看见和能修改什么；Harness 承载每次执行；Loop 决定任务如何长期推进。

Start small

第一版别做自动驾驶

先选读多、改少、证据清楚的场景：CI 失败分流、文档命令校验、PR 风险预检、依赖升级影响面扫描。

Checklist

工程检查表

1
写结构化状态，不把聊天记录当数据库。
2
候选结果和真实提交分开，副作用集中收口。
3
Maker 不做 Checker，验证要独立。
4
设置最大步数、预算、重试上限和停止条件。
5
高风险动作默认人工确认。
6
每轮留下 trace，用来改进 skill、memory 和工具。
