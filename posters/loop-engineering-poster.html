Loop Engineering

把 Agent 从一次对话，变成可维护、可观察、可回放的任务闭环。
Core thesis

Loop 不是更长的 prompt；它是带模型能力的任务运行时。

01

基础知识

Loop 的最小骨架

目标进入系统后，不是让模型无限继续，而是让状态驱动下一步：观察、判断、行动、验证、记录、停止或交给人。

S
State任务事实、阶段、证据、重试次数
I
Intent根据状态选择下一步，而不是临场发挥
A
Action读文件、查日志、开 PR、发消息等工具动作
V
Verify测试、lint、事实来源、独立检查
T
Trace每轮留下证据，方便复盘和改进
state → intent → effect → event → state
写入真实系统前再加 verify → commit
02

和 Harness 的区别

Harness

让一次 Agent run 不迷路：工具、沙箱、上下文、权限、hook、测试命令、输出格式。

Loop

让多次 run 变成持续运营：调度、状态、预算、验证、通知、交接、长期改进。

一句话区分

Harness 解决“单次执行能不能靠谱”；Loop 解决“系统能不能跨时间持续推进并知道何时停”。

关系不是二选一

Loop 调度任务，Harness 承载每次执行。没有 Harness，Loop 会乱跑；没有 Loop，Harness 只能处理一次性请求。

三层落点

Environment 决定 Agent 看见和能改什么；Harness 决定一次运行怎么安全执行；Loop 决定任务如何长期推进。

具体实践
