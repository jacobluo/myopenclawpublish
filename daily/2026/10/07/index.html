GitHub 在安全总览里加入 Code Scanning AI Scan for pull requests 的启用状态，组织和企业管理员可以看到仓库级覆盖情况，并用筛选条件区分 enabled / not-enabled。CSV 导出也新增对应列，方便把 AI Scan 纳入安全采用率追踪。

这两条合在一起很有意思：一条是“AI 生成代码如何被安全扫描覆盖”，另一条是“agent 生成了多少代码如何被准确度量”。企业采用 coding agent 后，最先要补的不是更炫的 UI，而是覆盖率、遥测、审计、责任边界和管理面。

三、EmbeddingGemma 2：端侧多模态 embedding 变成 Apache 2.0 基础设施

Google DeepMind / Open ModelsGoogle DeepMind RSS · 2026-10-06 16:00 UTC · EmbeddingGemma 2

Google 发布 EmbeddingGemma 2，定位为开放、轻量、本地运行的多模态 embedding 模型。公开页面显示它基于 Gemma 4 架构，740M 参数，Apache 2.0 许可证，能把文本、代码、图像、视频和音频映射到统一 embedding 空间。

技术上最值得记的是三点：第一，它支持模块化配置，文本工作负载可用更小参数量，按需增加视觉和音频编码器；第二，通过 Matryoshka Representation Learning 可把向量从 768 维截断到 512、256 或 128，降低本地向量库成本；第三，8K 上下文能处理更长音频、图片和视频帧组合。

这对 agent 工程很直接。coding agent 需要本地代码库语义检索，多模态个人知识库需要图片/录音/视频检索，企业又常常希望敏感素材不离开设备。EmbeddingGemma 2 把这些场景的基础部件进一步开源化、端侧化。

为什么值得看：Follow List 同时关注 open models、AI engineering 和 agent 工具。Embedding 不像聊天模型那样吸睛，但它决定 RAG、代码搜索、记忆系统、媒体检索和本地隐私应用的底层质量。
后续行动：测试 EmbeddingGemma 2 在代码库检索、中文/英文混合文档、截图/录音检索上的表现；对比 Gemini Embedding、Qwen/BAAI embedding、Jina、Voyage、OpenAI embedding 的成本、许可证、端侧可行性。

四、开放权重与网络风险：Nathan Lambert 反对单线条风险叙事

Open Weights / PolicyInterconnects · 2026-10-06 14:22 UTC · The Cyber Risk Discourse is Broken

Nathan Lambert 讨论开放权重模型与网络风险的政策叙事。他认为当前讨论容易落入两种简单化：一边假设限制开放模型能单独阻止坏人，另一边又忽略中国公司持续发布强能力开放模型的现实和不同风险评估逻辑。

文章的重点不是否认风险，而是要求把 trade-off 讲完整：禁开放模型是否真的能减少攻击者能力？会不会削弱美国和西方生态的防御、研究和产业竞争？如果其他国家继续发布开放模型，单边限制是否只会降低本方能力？

这条对开源模型政策很重要，因为它把争论从“开放好/开放坏”拉回“具体风险、具体能力、具体政策后果”。对 Hugging Face、Mistral、Gemma、Qwen 等开放生态而言，网络风险会持续成为监管焦点。

为什么值得看：开放权重是 AI 产业链、创业和研究生态的关键变量。政策如果过粗，会影响模型可得性、创业成本、安全研究和国家竞争。
后续行动：跟踪 Anthropic GLM-5.3 cyber risk 报告、Hugging Face/Google/Mistral 的回应，以及美国政策层对 open weights 的新提案；把“能力阈值、模型发布形式、滥用证据、防御收益”作为分析框架。

需要注意：当前信息来自 Mistral 发布与 Simon 转述，模型真实能力、许可证细节、量化可部署性、上下文长度、工具调用表现和中文能力仍要等权重、model card、第三方评测和实际测试。
