一、Simon Willison：Python 3.15 进入 Actions，自动守候上游状态变化

Developer Workflow / AutomationSimon Willison · 2026-10-10 23:58 UTC · Python 3.15.0 added to actions/python-versions · GitHub commit

窗口内第一条可核验更新是 Simon 记录 Python 3.15.0 已加入 GitHub Actions 的 actions/python-versions 仓库。这意味着项目可以把 3.15 加进 CI matrix，用真实 GitHub Actions 环境跑兼容性测试。

更值得注意的是工作流本身：Simon 提到自己此前让 ChatGPT 定时 clone/pull 该仓库，直到 stable 3.15 出现再提醒。这不是复杂 agent，却是很清楚的“事件守候”模式：周期检查、状态变化、通知人类、停止任务。

这个模式比大而全的 agent 更容易落地，也更容易评估。对开发团队来说，类似任务可以覆盖依赖发布、上游 issue 状态、CI 镜像更新、文档变更、API deprecation、价格页变化等。

为什么值得看：Follow List 长期关注 AI engineering 和 agent 产品。这个小例子把 agent 从“替你写代码”拉回“替你守候变化”：低风险、高频、可审计，适合作为个人和团队自动化的第一层。
后续行动：整理一组 watchlist 自动化：关键依赖版本、GitHub releases、RSS/Atom、docs changelog、价格页和 API deprecation；每个任务必须有停止条件、去重状态和简短通知模板。

二、Simon Willison：Dwarf Fortress 版本控制轶事，复杂系统绕不开基础纪律

Engineering DisciplineSimon Willison · 2026-10-11 00:52 UTC · Dwarf Fortress uses version control now

Simon 复查了 Dwarf Fortress 曾长期不用版本控制的旧闻，并发现 2023 年 Steam 版本前后，开发流程已经开始使用版本控制和 Discord 等协作工具。这个条目不是 AI 新闻，但对 agent 工程有现实含义。

AI coding agent 会让改动速度变快，也会让“我到底改了什么、为什么改、怎么回滚、哪次运行引入风险”变得更重要。版本控制不是形式主义，而是 agent 能安全进入真实代码库的最低运行轨道。

和昨天 GitHub Copilot for JetBrains 的 worktree/session 可靠性改进放在一起看，主线很一致：agent 越常驻，越需要把变更隔离、对话上下文、工具调用、分支和回滚关系管理清楚。

为什么值得看：它提醒我们不要只追模型能力。真实生产力的上限往往由版本控制、CI、review、审计日志、权限边界和恢复路径决定。
后续行动：把 coding agent 默认运行规则写清楚：新任务独立分支或 worktree；改动前读状态；改动后跑最小验证；外部提交前展示 diff；失败时保留轨迹而不是静默重试。
