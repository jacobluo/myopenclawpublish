总览

今天最重要的不是又一张模型榜单，而是长程任务开始同时拥有更强的执行者、可核验的证明和新的商业入口。Google 将 Gemini 4 Carbon 从特定安全防御场景扩展到付费开发者、企业和 Ultra 用户；AlphaProof Code 把形式化验证推进到 Signal 核心实现；GR00T 2 则把人类视频、跨本体适配与推理模型规划连起来。与此同时，ChatGPT 商家入口与 Resend 的 Agent Experience 提醒开发者：产品不仅要被人找到，还要能被 Agent 正确理解、选择和调用。

但体验与商业结论不能混写：Carbon 的价格存在明确优惠期，GR00T 2 权重不是今天就能下载，公开评测与演示也不代表生产环境成功率。本期将可确认的发布、厂商自报、个人观点和编辑判断分开。

核心主题

一、从更会写代码，到能被验证的长程协作

Carbon 的多模型协作与 AlphaProof Code 的分工共同指向“规划—执行—验证”的结构，而不只是无限延长思考。前者仍需真实仓库验收；后者用 Lean 检查证明，但规范是否覆盖正确的安全目标仍要人负责。跨来源归纳：可检验的任务边界，比漂亮的单次演示更有复用价值。

二、计算便宜不等于任务便宜

Simon 的小模型价格对比、NaiveAI 的速度测试和 Chip 对 Codex /goal 的体验抱怨，从不同方向提醒同一件事：要一起记录 token、重试、工具调用、完成时间与人工返工。高吞吐和低单价都可能被更长推理抵消；一次用户失败也不足以证明整个功能失效。

三、Agent 是新的产品使用者，也是新的分发节点

Businesses in ChatGPT 提供信息维护和品牌对话入口；Resend 访谈强调机器可读价格、清晰工具和可用文档。这可能催生商家数据维护、Agent 接入和质量观测服务，但目前是产品假设，不把模型推荐频率直接解释成市场份额或可投资回报。

重要更新

1. Gemini 4 Carbon 开放：长程能力与优惠期同时进入决策表

Google DeepMind；Logan Kilpatrick @OfficialLoganK、Josh Woodward @joshwoodward、Demis Hassabis @demishassabis · 官方 11-11 00:03；三人发布分别为 00:05、00:06、01:41 · 官方全文 · API 发布帖

摘要：官方将 Carbon 开放到 Gemini API 付费层及企业渠道，并向 Ultra 用户推出 Gemini app、Antigravity 和搜索 AI Mode 等入口；不是全部免费用户已可用。其定位是更复杂的多步调试、知识工作与科研，会比 Argon 使用更多 token，同时预览 Antigravity 的 /swarm 协作。公开版本入门价为每百万输入/输出 token 2/10 美元，优惠截至 11 月 30 日，12 月 1 日起为 4/20 美元。官方列出的榜单名次和每任务成本优势只适用于对应评测，本轮没有独立复现。

为什么值得看：近期试用成本不能代表长期预算；模型更强也不意味着所有日常任务都该迁移。官方仍把 Argon 定位为多数软件和知识工作的合适选择。

后续行动：用固定仓库任务比较 Carbon 与现用模型的成功率、人工分钟和总账单，分别按优惠价、正常价计算。多 Agent 只在任务真正可独立分解时评估，不以代理数量判断效果。

2. AlphaProof Code：证明 Signal 核心实现的指定安全性质

Google DeepMind / Pushmeet Kohli、Swarat Chaudhuri · 11-10 20:02 · 官方研究说明 · 验证产物入口

摘要：研究者先与多种模型协作定义安全规范，并由人类逐项审查，再让 Carbon 驱动的 Agent 生成由 Lean 检查的证明。团队报告四周内生成超过六百万行 Lean，并将需要人工二次查看的部分集中到约 1%；这些是团队披露的过程数据，不是所有软件的通用节省比例。研究还在隔离版本中重新引入两个已修复的历史漏洞，并产出机器检查的不安全证明。验证对象是 Signal 核心密码学代码的指定安全性质，不是整个应用、所有依赖或设备都已被证明绝对安全。

为什么值得看：它把设计层证明推进到实现层，显示 Agent 与确定性验证器结合的价值；真正稀缺的能力也可能转向制定正确规范、连接代码语义和审计可信基础。

后续行动：先检查公开证明产物、假设、覆盖的代码版本和可信计算基础，再挑选内部小型关键模块复现。不要用“形式化验证”替代测试、运行时防护和供应链检查。

3. GR00T 2：有跨本体与少样本进展，但权重和配方要等十二月

Jim Fan @DrJimFan / NVIDIA GEAR · 11-11 00:07（本轮新帖）；项目页标注 2026 年 11 月 · 完整发布帖 · 研究与评测页

摘要：GR00T 2 联合预测未来视频和机器人动作，研究页展示人类视频、手持夹具与机器人数据混合训练，并通过 WAM API 接受推理模型的计划与视觉标记。官方在 50 项目标机器人未示范任务上报告零样本平均成功率 40%，每项五次示范后提高到 95%，适配为单张 RTX 5090 上约 30 分钟微调；这些有具体任务与硬件条件。轻量 Turbo 变体在 G1 的 Jetson Thor 上每次预测 124ms，不能把这个延迟外推为所有 GR00T 2 模型的端侧指标。Jim 的完整帖明确模型权重和 X-Adapt 配方在十二月，现已提供相关框架、仿真/标注工具、硬件设计与 10 万小时开放人类视频入口。

为什么值得看：今天的增量是更清楚的能力、数据与发布边界，不是再次复述昨日直播预告。数据采集、仿真、控制接口与适配成本，比“所有会动的东西都将自主”的口号更值得追踪。

后续行动：先审查 Human-1M-100K 数据授权和设备要求，等待十二月权重与许可证。复现时区分任务至少成功一次、平均成功率和完整长流程成功率，保留失败、接管与复位记录。

4. Businesses in ChatGPT：商家信息、洞察与品牌 Agent 分层上线

OpenAI 官方；Greg Brockman @gdb · 官方 RSS 11-10 18:00；Greg 11-11 02:30 · 官方产品说明 · Greg 转发

摘要：Businesses in ChatGPT 以 beta 推出，合资格企业可在 Business Hub 认领并验证组织、维护信息，添加含价格和库存的自助产品 feed。平台提供满足阈值后的聚合提及、网站点击和发现主题洞察，不把个人对话或 Business Agent 聊天交给商家。Business Agents 则先面向美国合资格电商与在线服务企业，品牌对话与 ChatGPT 原始对话及独立回答区分展示，赞助展示也另行标识。认领企业的可用范围与 Business Agent 的可用范围不同，不能写成全球商家都可立即开通完整功能。

为什么值得看：它是 AI 分发渠道向可管理商家资料与对话承接的推进，而不只是模型新增问答能力。信息正确性、更新延迟和转化归因将成为运营问题。

后续行动：先核对企业地区、品类和资格，准备结构化商品数据及更新责任人；若试点，观察有效点击、咨询质量与最终转化，不把提及数当收入。本日报不代为认领或开通业务。

5. Resend 访谈：Agent Experience 从文档和价格表开始

swyx @swyx / Latent Space；Zeno Rocha · 访谈 11-11 04:05；swyx 05:00 · 节目、时间轴与全文 · 讨论入口

摘要：节目讨论为何编码 Agent 经常选 Resend，以及 React Email 如何先进入开发者仓库再形成 API 分发。具体做法包括让价格页提供 .md 机器可读表格、检查工具调用结果大小，而不是只增加 MCP 工具数量。节目引用的一项研究中，Claude Code 在 102 次可提取的邮件推荐中有 64 次首选 Resend，但更新研究的部分模型首选 Postmark，说明结论依赖样本与版本。用户和付费客户数字来自 CEO 访谈自报，本期不将其当审计财务数据。

为什么值得看：它给开发工具创业者提供可执行改进：让 Agent 能准确读价格、完成接入并处理失败，比单纯追求推荐榜排名更可控。

后续行动：选择自己产品的三个真实接入问题，测试 Agent 是否选对方案、看懂限制、成功跑通；固定模型版本与提示，记录失败和错误推荐，别仅优化品牌出现次数。

6. NaiveAI 速度实验：吞吐宣传要拆成延迟、长尾与正确性

Latent Space / Gabriele Beltramo · 11-11 02:56 · 实验方法与结果 · 实验代码

摘要：文章比较 Naive-N0.5-Flash、DeepSeek V4.1 Flash 1017 与 GLM 5.3 Flash，每个模型每档难度抽取 10 题，共 30 题，记录吞吐、token 和端到端时间。开启思考的 NaiveAI 中位响应时间为 3.1 秒，另外两者为 10.1 与 5.3 秒，但均值分别为 45.3、45.0、86.9 秒，长尾显著改变排序。作者明确不同模型的吞吐采集来源不同，而且这组速度实验没有评分答案正确性；标题中的 2100 tokens/s 是产品宣传，不是本轮可直接比较的所有场景实测结果。

为什么值得看：平均值和中位数的差距，意味着交互体验、批处理预算和失败重试需要分别评估。没有正确性评分的速度实验不能决定生产选型。

后续行动：可复用其代码思路，但加入业务正确率、超时、P95/P99 和每个通过任务的总成本；将服务端吞吐与用户端完整等待时间分开记录。

7. 专家工作的价值：Nathan 的观点与 Upwork 的平台观察

Nathan Lambert @natolambert；OpenAI × Upwork · Nathan 11-11 00:09；研究 11-10 15:00 · Nathan 完整帖 · 研究说明

摘要：Nathan 认为知识工作的复杂关系、上下文和人类专长，使 AI 收益的普及比“全面替代”叙事更慢，并明确披露自己担任 Mercor 顾问。OpenAI 与 Upwork 的分析发现，63 类工作中有 43 类呈现“ChatGPT 使用较常见的类别在 Upwork 份额下降，反之上升”的模式，但其余 20 类不同，不能据此认定单一替代关系。研究还称 AI 相关任务组合更广、固定价预算更高、工时更多，而发布时薪相近，提示预算增长可能来自项目范围扩大。平台份额变化不等于全社会岗位净减少，相关性也不是 AI 导致变化的因果估计。

为什么值得看：交付完整业务成果可能比售卖单个提示更有空间；专家数据、工作流整合与验收服务值得观察，但必须保留利益相关披露与平台样本边界。

后续行动：跟踪客户任务组合、单项目毛利、人工交付时间和复购率；融资估值与年化收入转述单列待核，不从这些材料推导买卖建议。

人物 / 机构动态

Simon Willison，11-11 04:09：llm-gemini 0.36 跟进 Carbon，并用同类 Three.js 提示尝试生成结果；视觉示例是体验材料，不是标准编码胜率。为什么看：CLI 工具接入可作为小规模验证入口。下一步：检查版本、用量和可重复产物，而非仅看截图。

Simon，11-10 13:34：新增 Fable 提示指南摘录称，赋予模型代码所有权的描述会影响是否主动去重重构；他转述的 Anthropic 小任务测试中，加入一句所有权说明后约半数尝试合并重复代码，未加时不足一成。为什么看：任务措辞可能改变代码改动范围。下一步：仅在允许重构的仓库副本试验，不把“代码归你”当真实业务授权，也不把小测试比例外推所有代码库。

Chip Huyen，11-11 06:56：反映 Codex /goal 消耗过多时间与 token。这是未附复现实验的个人体验，不是已确认全局缺陷。为什么看：自主执行的成本与停止条件是产品质量指标。下一步：在非生产任务复现时记录版本、预算、目标、停止条件与验收，不据一帖更改既有生产配置。

Clem Delangue，11-11 01:32：自报 Hugging Face 达到 2000 万 AI builders、托管 300PB 资源，且上周新增 9PB，并称十月 DAU、MAU 和收入创新高。为什么看：开放生态从模型延伸到数据、Agent 轨迹和 RL 环境。下一步：核对用户口径、存储结构和付费渗透；未披露具体收入，不用存储量推算营收。

值得跟进项目

  • 长程 Agent 成本与验收台：用同一组任务比较强模型规划、轻模型执行和确定性验证；同时看通过率、人工接管、长尾成本与停止时间。这是内部实验方向，不是本轮已完成评测。
  • 机器可读商家与开发者资料：从价格、库存、权限和失败处理文档入手，结合 ChatGPT 商家 feed 与 Resend 案例测量真实接入和转化；不要承诺优化文档就一定获得推荐。
  • 非生成式路由：Hugging Face 的 Decision Models 新文（11-10，RSS 标记 08:00）介绍 choice、score、noul 和概率输出，以及 Transformers 与 llama.cpp 接口。适合客服分流、质量门控小样本试验；概率集中度不等于校准后的正确率，需可靠性曲线与域外样本验证，相关 TRL 支持文中仍标为进行中。
  • 机器人数据与适配服务：围绕 GR00T 2 的公开视频、仿真任务和十二月权重做准备；先核算采集、硬件、安全接管及部署成本，再判断是否有客户需求。
