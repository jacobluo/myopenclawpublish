总览

今天最值得看的不是新模型名，而是 Agent 如何接上真实数据、业务系统和验收机制。Clay 的访谈把“做一个自己的 Agent”与“让所有 Agent 都能使用自己的业务底座”放在同一张产品地图上；Karpathy 的数据地图展示长时间编码与数据整合的可见成果，也暴露覆盖完整性问题。开源侧，AMD 推理看板、Nemotron 文档解析与通信训练实验提供了更具体的测量入口。

本轮以 Follow List 为控制面板，按 high 优先、兼顾 daily 来源，检查 31 个 active X 账号，其中 22 个 high；公开页面均返回 HTTP 200，提取窗口内 16 条本人账号可见帖子，URL 与既有发布索引无重复。12 个 RSS/Atom 端点中 11 个可解析，共取得 7 条窗口内条目；另检查 explainx sitemap 与播客 JSON。公开时间线只是局部视图，HTTP 200 或未见新帖都不意味着完整覆盖。

核心主题

1. 入口可以被替换，数据与执行底座不一定

Clay 允许用户从 Claude Code、Codex 等外部工具访问业务能力，swyx 对 Zapier 转型的观察也指向连接器与行动层。编辑判断：如果用户工作场所在编码 Agent 中，强迫其回到专有聊天框可能是摩擦；可复用的身份、数据、业务函数和执行记录更值得持续投资。这是产品假设，不是已证明的市场份额变化。

2. 产出规模不能替代数据与结果验收

数万行代码、海量企业分类或更快文档解析，都需要追问覆盖、来源、错判和返工。工程推论：应把“每个被验收结果的总成本”作为单位，将推理费、数据采购、复核和失败恢复一起计算，而不是只看 token 价格。

3. 多 Agent 的关键是信息结构，而不是人数

Hugging Face 的小模型通信实验故意让每个成员只看到部分输入，适合研究协作协议，却不能证明多 Agent 普遍优于单 Agent。与 AMD 看板分开测预填充、生成及上下文长度相似，好的评测先明确变量，再讨论扩展。

重要更新

1. Clay：从受限工具循环转向编码 Agent 与开放业务能力

Latent Space / Jeff Barg，Clay Head of AI；对应 Follow 来源 swyx · RSS 发布时间 11-27 07:02
官方节目文章与时间戳 · Clay 官方 CLI/API 公告

摘要：节目文章称，早期 Sculptor 擅长加列，却不擅长实现约到合格会议这样的完整目标；团队随后采用 Pi harness、云沙箱和 Clay CLI，并补充 CRM 与业务数据视图。Jeff 表示自有 Agent 与外部 harness 的使用已接近各半，客户也不愿反复手选模型，团队准备引入自动路由。已核对 Clay 的官方公告：插件、CLI 和 API 的普遍可用日期为 9 月 15 日，不是今天首发；本轮读的是官方节目文章，未收听整期音频或逐字稿，经营与用量数字仍属嘉宾自述。

为什么值得看：业务软件可能同时需要自有界面和无头能力；对外暴露稳定业务函数，比复制一套聊天入口更接近可持续产品价值。

后续行动：挑一个只读客户研究任务，对比自有界面与外部 Agent 的数据覆盖、权限、执行记录和输出正确率；写 CRM 或发起营销必须另行授权，本文不执行。

2. Clay 的成本与调度：分类便宜之后，瓶颈转向业务闭环

Latent Space / Jeff Barg · 11-27 07:02，同一期访谈的工程专题
来源全文

摘要：Jeff 粗算用分类器处理约 4,000 万家公司可花约 1,500 美元，但明确该方案尚未部署到生产，不能理解成获取和清洗全球公司数据的全成本。其团队使用 BullMQ，并为按行运行导致的突发负载加入限流、暂停恢复和公平调度；访谈还称模型尚不能稳定定位长轨迹中的真正错误，容易把耗时步骤误判成根因。关于数千万美元推理支出才值得后训练的阈值，也是嘉宾经验判断，不是适用于所有团队的定律。

为什么值得看：随着基础分类变廉价，数据接入、深度研究、任务公平性和异常定位更可能决定用户体验。

后续行动：用一个小批量任务记录数据费、误判、人工分钟数和最终合格线索成本；压力测试大客户批次是否饿死小客户请求，并模拟供应商限流后的恢复，避免仅用推理单价估算商业模式。

3. Karpathy 的 USACiv：长时间自主编码，仍需检查地图空白

Andrej Karpathy @karpathy · 11-26 10:31
完整原帖 · 公开项目入口

摘要：Karpathy 自述使用 Claude Code 和 Opus 5.5，将 Census、BEA、BLS 等 31 个公开来源整合为美国文明风格地图，约耗时 7 小时、生成 4.5 万行代码。帖子描述 25 公里六边形网格、524 个都会区及多个数据视角，也明确承认遗漏部分州和领地。项目入口返回 HTTP 200，但静态抓取仅见加载外壳，本轮未操作地图、核对底层数据或审计代码，规模与完成度按作者自述记录。

为什么值得看：自然语言驱动数据应用的门槛正在降低，但“能展示”与“覆盖完整且统计口径一致”是不同的验收标准。

后续行动：抽查三个地区的原始指标、年份和单位，列出缺失地域，检查跨来源连接键与重采样规则；若做产业地图，先保留每个格子的来源和更新日期，不以代码量作为质量证明。

4. llama.cpp × AMD：把硬件吞吐变成可追踪的公开实验

ggml-org / Hugging Face，开放模型生态补充源 · RSS 11-26 19:37
官方看板说明与数据入口

摘要：新看板按硬件、模型、量化和 llama.cpp build 展示性能，当前列出 Radeon 8060S 与 Radeon AI Pro R9700S。官方将 PP512 与 TG128 分开，分别测 512 输入 token 处理和 128 token 生成，基础图表从零上下文开始，另提供上下文扩展视角；工作流每周运行，每种配置重复 10 次，并公开结果数据。它是特定硬件和工作负载的观测工具，不是全体 AMD 设备或真实业务的通用速度结论。

为什么值得看：版本、量化、上下文和预填充/生成差异可能改变采购与部署判断，单张 tok/s 截图容易误导。

后续行动：固定 build、模型和量化，再用真实提示长度与目标上下文复测；增加质量、内存、功耗与尾延迟，之后再比较每个有效任务的设备总成本。本轮未跑硬件实验。

5. Nemotron 3.5 Parse：开放数据、可验证奖励与按难度再解析

NVIDIA / Hugging Face，文档与开放模型补充源 · RSS 11-26 13:05
官方技术文章

摘要：NVIDIA 在既有 Parse 3.5 基础上补充合成图表、表格和多语言 OCR 数据、微调配方及 DFlash2 推理方案；这不是把基础模型重新当作今日首发。文章的匹配开发检查点比较中，循环标记页数从 126 降至 29；单 H200、BF16 的原生单遍测量里，DFlash2 相对关闭推测解码的 Parse 3.5，在并发 1 和 512 下分别加速 7.62 倍与 1.52 倍。双遍/三遍可对困难区域再处理，但增加请求量；牙科表单的高成功率来自同一合成生成器的留出集，不能直接推及真实异构扫描件。

为什么值得看：表格错一行可能让财务或研究结论完全相反，结构正确与完整终止往往比纯 OCR 字符准确率更重要。

后续行动：先用真实扫描表格、无数值图表和跨语言样本构建留出集，检查单元格关系、数字、边界框与终止；在相同质量标准下比较单遍和局部再解析成本，再决定是否微调。

6. 通信训练实验：四个小模型学会协作，不等于通用群体智能

Ben Burtenshaw、Kashif Rasul / Hugging Face · RSS 11-26 08:00，处于窗口起点，按 feed 字段纳入，不视为精确首发时刻
原文、实验与复现入口

摘要：四个 Agent 共享 Qwen3-0.6B 策略，各自只见一个数字，需交换信息后输出完整排序；训练初末窗口成功率从约 6.6% 到 82.3%，75 步检查点在 32 个留出问题中解出 26 个。文中约 37.4% 的 token 降幅是训练窗口测量，没有保留相应留出集效率数据；93.2% 来自所引论文的 200 步结果，不是本次 75 步检查点。由于单个 Agent 根本看不见全部输入，这个实验测试的是通信学习，而非相同完整输入、等 token 预算下胜过单 Agent。

为什么值得看：它把协作收益、重试收益与额外算力区分开，避免用“更多成员”解释所有进步。

后续行动：若评估生产协作，增加完整输入单 Agent、独立并行、可通信团队三组，匹配预算并比较成功率和总延迟；本轮仅阅读文章，未执行训练代码，也未复现其成本估算。

7. SQLite 备份：旧工具的新提醒，比强行换栈更实用

Simon Willison @simonw · 11-26 14:08
Simon 的笔记 · SQLite 官方文档

摘要：Simon 再次介绍 sqlite3_rsync：通过 SSH 生成一致性快照，不必先在源机器放下一份完整副本，并能增量同步。它是 2024 年已出现的工具，不是今日新发布；官方文档指出普通 rsync 不理解活动数据库事务，而 sqlite3_rsync 同步期间副本只读，远端也需安装该工具，混用某些新旧版本还需注意协议协商兼容问题。

为什么值得看：轻量 Agent 常用本地 SQLite 保存状态，磁盘余量不足或不一致备份会直接影响恢复能力。

后续行动：先在测试库验证版本兼容、恢复与完整性，再规划生产快照；未在本任务中安装工具或改动任何数据库。
