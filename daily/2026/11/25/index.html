总览

今日主线：模型能提出更多答案，但真正稀缺的是证据、执行基础设施和业务验收。OpenAI 展示蛋白设计湿实验与公开天文数据搜索，价值在于把假设送到外部检验，而不是宣称科学问题都已解决；iFood、Harvey、Datasette 则展示如何把能力变成可运行、可计费、可交互的工作流。

核心主题

1. 科研 Agent 的关键是“提出可检验假设”，不是宣告结论

蛋白结合实验、天文后续观测、档案原件核对是三种不同的验收机制。编辑判断：值得追踪的科研基础设施，是能把模型生成的候选、筛选步骤、失败样本和外部证据串成链条的系统；单个亮眼案例不能证明普遍科研能力，也不能把实验室结合信号等同于药物有效。

2. 企业价值取决于每个合格结果，而不是调用量或 PR 数

iFood 强调异步沙箱与固定流程；Hamel 提醒不要把合并数量当经济价值；LangChain 的知识维护则说明输入质量会随业务变化而退化。工程推论：应统计每个被接受修复的总成本、返工和维护负担，把推理费用、运行环境和人工审查放在同一张账单里。

3. 开源机会从通用榜单转向任务、模型与运行框架的匹配

Harvey 的法律后训练与 Hugging Face 的 harness adapters 指向领域分布和执行环境适配，而不是一个基座全面胜出。训练配方是否可复用、验证器是否会误判、效果能否跨任务保持，比“开源已到前沿”的口号更值得核查。

重要更新

1. 蛋白设计：有湿实验信号，但实验管线仍用了专用模型

Greg Brockman @gdb / OpenAI、Onava · Greg 11-25 05:30；官文 RSS 11-24 21:00
Greg 原帖 · 官方研究解读 · 预印本 PDF

摘要：OpenAI 报告 GPT-6 系列可以用推理和通用代码产生蛋白结构或序列设计；结构生成环节没有调用专用生物生成模型，但湿实验候选的序列补全和筛选仍使用了专用模型。官文称，基于 GPT-6.2 结构设计的 322 个 minibinder 中，35 个显示目标结合信号，覆盖所选 5 个靶标。内部研究模型在多项计算任务上表现更好，但完整蛋白结构预测仍是明显弱项；这是预印本与团队实验报告，不是临床有效性结论。

为什么值得看：最重要的不是“通用模型取代生物模型”，而是自然语言约束、代码搜索与专业实验流程开始连接。需要逐段看清谁生成、谁筛选、谁验证。

后续行动：优先核对论文的样本筛选、结合判据、失败样本和训练污染讨论；本轮已读官文，未重跑论文代码、重算指标或独立复现实验。

2. 系外行星搜索：候选信号出现，尚未确认新行星

Greg Brockman @gdb / OpenAI · Greg 11-25 03:14；官文 RSS 11-24 19:00
Greg 原帖 · 完整案例

摘要：OpenAI 介绍 Kevin Bond 与 Ethan Byrd 分别用 Codex、Astra 搜索公开望远镜数据，形成潜在系外行星线索。文章称，SETI 研究者独立找到了 Bond 提交的两个相同信号，Byrd 的强候选已交由 TESS 相关研究者进一步分析。独立重现光变信号不等于确认行星；双星、仪器噪声等替代解释仍需排除，后续可能持续数月或更久。

为什么值得看：公开数据降低了科研参与门槛，模型主要帮助构建搜索与候选检查管线；专家跟进仍不可省略。

后续行动：跟踪候选标识、周期与后续观测记录，等待可审查的论文和正式目录；不要把扫描星体数量或候选数量当成发现数量。

3. 历史研究：22 分钟提出归属假设，档案确认发生在之后

Greg Brockman @gdb、Simon Willison @simonw；原作者 Mark Humphries · Greg 11-25 03:06；Simon RSS 11-25 00:53；原文日期 11-24
Greg 转述 · 历史学家原文 · Simon 阅读笔记

摘要：Humphries 报告，GPT-6.2 Astra 在约 22 分钟内为耶鲁收藏的匿名 1808 年画册提出 Chabot 作者假设，并指出可订购的旅行日记线索。作者随后取得档案，用笔迹、行程和日记中描绘要塞的记载支持归属；这段线下取得证据的过程并不包含在 22 分钟内。他还称 Fable 5.2 用同一提示得到同一人名，但未找到关键日记；本轮读到原文，未独立逐页核对档案。

为什么值得看：真正可迁移的是候选排除、跨文献关联与主动提出验证来源，不是把模型确信程度当成史学证据。

后续行动：阅读原作者给出的馆藏引用及证据链，区分模型完成、人工检索和后续确认；原文夹带的数学突破概述不属于本轮核验结论。

4. iFood：规模化 Agent 靠异步运行时，而非不断更换大模型

OpenAI 官方客户案例 / iFood · RSS 11-24 08:00（边界条目；官网仅列日期）
官方客户案例

摘要：iFood 案例描述了面向 15,000 个代码仓库的 Remote Agents Platform：通过 API 派发任务，在隔离沙箱执行，再返回 merge request。页面自报累计超过 25,000 次运行、平均每次推理费用 0.04 美元，并称内部安全平台修复数量翻倍以上；这些不是第三方审计或完整交付成本。流程前后采用确定性步骤，中间由模型执行，Structured Outputs 用来整理结果，但格式契约不自动保证修复正确。

为什么值得看：“环境准备—执行—结果收集”的公共底座，比为每个团队重复造 Agent 循环更容易形成规模效应。

后续行动：选一种重复依赖修复任务，记录被接受修复率、回滚率、沙箱费和人工审核时长；不能直接用 0.04 美元推算一个有效修复的总成本。

5. Harvey：法律任务后训练取得进展，榜单口径不能泛化

Clem Delangue @ClementDelangue；Harvey @harvey · Clem 11-25 02:44；Harvey 原帖 11-25 00:05
Clem 转述 · Harvey 原始声明

摘要：Harvey 表示，沿用 Tenet 配方对 Meta、NVIDIA、Reflection、Thinking Machines 的四个美国开放权重模型进行后训练，相关结果可与非美国模型竞争。其称 Muse Spark Open 首次在 Legal Agent Bench 超过 30% all-pass；这是机构披露的特定法律基准结果，不是普遍法律可靠率。已读完整原帖，但尚未独立取得并复核数据划分、评测实现及模型许可。

为什么值得看：领域数据、反馈和严格验收可能是应用公司的护城河；开放权重使所有权与部署选择更多，但不是自动免除法律责任。

后续行动：继续追踪技术报告、权重或可用接口，核查 all-pass 的题目级定义与失败类型，再用本地真实合同任务评估，不直接生产部署。

6. Datasette：聊天生成图表，且能跟上用户在面板中的修改

Simon Willison @simonw · charts RSS 11-24 12:24；agent RSS 11-24 11:45
图表集成说明 · charts 0.2a0 · agent 0.7a1 说明 · agent 版本页

摘要：datasette-charts 0.2a0 在此前图表插件基础上接入 Datasette Agent，让自然语言请求调用同一套图表建议与生成工具。Simon 的演示还展示：用户在侧面板改了图表，Agent 再解释时能读取更新后的内容；datasette-agent 0.7a1 为此改善 fragment hash 导航。两项版本入口均返回 HTTP 200，本轮未登录演示、安装或逐项实测，所以按作者演示报告，而非已验证所有交互。

为什么值得看：实际增量是共享状态的双向协作，而不是只把一次性静态图塞进聊天。对财务、运营数据工具尤其有参考价值。

后续行动：用固定数据检查筛选、面板状态和查询结果是否一致；保留 SQL、时间范围与聚合口径，防止用户改图后解释仍基于旧状态。

7. 卡兹克：体验审查从列组件转向检查状态变化

数字生命卡兹克 @Khazix0918 · 创建时间 11-24 14:12；页面标记已编辑
完整原帖

摘要：卡兹克分享两组个人产品审查提示：减少让用户承担的系统判断，及按出现、消失、加载、完成、出错等状态变化逐项检查动效。长帖强调统一反馈、克制、可中断、性能与“减少动态效果”适配，并让不同模型参与方案和复核。它提供的是工作方法与主观体验，不是跨项目对照实验，也不构成未经验收就自动合并上线的通用授权。

为什么值得看：这把“界面高级感”拆成可检查行为，容易转化为交付标准；体验改进与更多装饰动画不是同一件事。

后续行动：在一个真实流程上走完提交、等待、失败、撤销和重试，分别检查窄屏、键盘与减少动态效果设置；最后看任务完成和误操作是否改善。

8. 工程方向：多 Agent 的机会在身份、隔离、观测与状态管理

swyx @swyx；Simon Willison @simonw · swyx 11-25 07:29；Simon 文章 RSS 11-25 07:02
swyx 完整观点 · Simon：一年三个能力拐点

摘要：swyx 将工程机会归纳为大规模协作、文件与运行基础设施、Agent 自身身份与授权、隔离及可终止的观测系统；文中千倍规模是设想，不是实测吞吐。Simon 则回顾从可用编码到目标驱动执行，再到 3D 与游戏迭代的个人能力拐点。他的“Fable class”是个人分类，不是行业标准；两篇都适合当研究议程，而不是市场规模或投资回报证明。

为什么值得看：即使模型能力继续改善，任务状态、权限边界和验收仍是产品必须承担的工程责任。

后续行动：先为单个持续任务实现独立身份、最小权限、可关联事件、可恢复状态和取消机制，再评估扩大并发；不按模型调用数衡量产品价值。
