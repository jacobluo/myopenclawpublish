01

MigraQ 能做什么

覆盖云迁移全生命周期的 12 项核心能力

MigraQ 不是单一工具，而是一整套迁移能力矩阵。按迁移的自然阶段，可以分成四大能力组——从摸清家底，到选型算账，再到方案设计与落地执行。

01
发现与盘点
搞清楚「我到底有什么」
多云资源扫描
cmg-scan
解决不知道账号下到底有多少资源、分布在哪些地域、什么规格、什么状态，手动盘点耗时易遗漏。
价值一键生成标准化 Excel 资源清单 + 可视化 HTML 报告，覆盖计算、存储、数据库、网络、安全全部产品线；结果可直接喂给下游的规格推荐与成本分析。
阿里云 / AWS / 华为云 / Azure / GCP / 腾讯云 / 火山引擎
账单 / 报表解析
cmg-import
解决手头有各种格式的云账单或资源清单（CSV / Excel / 截图），格式千奇百怪，无法直接用于分析。
价值AI 智能识别文件来源，自动提取规格、地域、数量，输出标准化 JSON，对接后续选型与 TCO；支持 AKSK 方式直接拉取云厂商账单。
资源评估表拆分
cmg-assess
解决拿到的摸底表是汇总级别（如「29 个 RDS，共 58 核」），没有单实例规格，无法做精准对标。
价值自动将汇总数据拆分为单实例规格（总规格 ÷ 数量），推导出合理的单实例配置，输出标准化资源清单。
资源拓扑分析
cmg-topology
解决不清楚云上资源之间「谁依赖谁」——哪些服务器连哪个库、负载均衡挂了多少后端、安全组覆盖了哪些资源。
价值自动采集多云资源间依赖关系，生成可视化拓扑图（架构图 + 关系图），支持地域 / VPC / 类型筛选，看清迁移依赖链与分批边界。
网络拓扑分析
cmg-network
解决不清楚云上网络「怎么连的、流量怎么走」——VPC 互联、入站出站链路、南北 / 东西向流量路径。
价值自动采集网络架构数据，生成 8 层分级网络架构可视化 HTML，覆盖 Inbound / Outbound / East-West 三大场景，评估迁移后连通性与安全风险。
02
选型与对标
搞清楚「迁到腾讯云用什么」
智能规格推荐
cmg-recommend
解决源端有几百种规格（阿里云 ecs.c7.4xlarge、AWS m6i.2xlarge……），不知道腾讯云对应什么，手动查表易出错。
价值自动将源端规格映射为腾讯云等价规格，按「同价代次优先、同配价格优先」双原则选最优候选，输出对标结果 JSON。
CVM / CBS / MySQL / Redis / MongoDB / PostgreSQL / ES / CKafka / CLB / COS / CFS 等
TCO 成本分析
cmg-tco
解决想知道迁移到腾讯云后「到底能省多少钱」——源端月费 vs 腾讯云月费，用数据支撑迁移决策。
价值基于选型结果跨 6 个云厂商批量实时询价，生成 TCO 对比报告（Excel + 可视化 HTML），输出月 / 年节省金额，支持按需与包年包月口径。
03
方案设计
搞清楚「迁移应该怎么做」
迁移方案咨询
cmg-advisor
解决不知道某个特定产品（PostgreSQL / Redis / ES / Kafka）的迁移最佳实践、割接策略、注意事项。
价值接入云知架构师知识库，基于历史项目沉淀输出产品级迁移方案、步骤、风险点与参考文档，覆盖 20+ 产品迁移场景。
LandingZone 规划
landing-zone-design
解决第一次上腾讯云，不知道账号体系怎么建、VPC / CIDR 怎么规划、CAM 权限怎么设、安全基线怎么配。
价值自动生成完整 LandingZone 方案（HTML 摘要 + XLSX 主方案），覆盖多 / 单账号 / 迁移三种模式，含账号体系、CAM、CIDR、安全基线等 13+ Sheet。
网络方案设计
network-solution-design
解决需要一份可评审的网络设计方案，含 VPC / CIDR 规划、Egress / Ingress、跨云网段冲突分析、SD-WAN / CFW 等。
价值基于迁移场景输入产出 HTML 设计文档 + XLSX 资源清单，覆盖多账号网络、双活 / 多活拓扑、跨云专线 / VPN 对接等。
服务依赖分析
service-dependency
解决不知道微服务之间怎么依赖——谁调谁、谁共用库、谁走消息队列，迁移批次怎么拆。
价值通过 LB、API 网关、注册中心、消息队列、K8s ConfigMap 等多数据源采集依赖，输出依赖清单、架构图与分批迁移策略。

你该怎么用 MigraQ

不是学某个产品怎么迁，而是掌握「这个工具怎么用」

MigraQ 的使用门槛极低——你不需要背命令、记参数，只要像跟一位迁移顾问对话一样，说清楚自己的需求即可。

核心原则：把它当作一个「虚拟迁移顾问」来对话

MigraQ 不是搜索引擎，也不是命令执行器。你不需要学习复杂的指令语法——只需要像跟同事沟通一样，用自然语言描述你的迁移需求。

✓ 正确的提问方式

  • 帮我扫描一下阿里云杭州地域的 ECS 和 RDS
  • 我有一份 AWS 账单 Excel，帮我看看有哪些资源，迁到腾讯云大概多少钱
  • 我们要把自建机房 200 台服务器迁到腾讯云上海，帮我规划一下
  • 阿里云 8C16G 的 ECS 对应腾讯云什么规格？贵不贵？

你不需要做的事

  • 不需要记住任何技能名称或命令
  • 不需要了解内部技术细节（MigraQ 会自动判断该用什么能力）
  • 不需要严格按照固定格式提问
一句话总结：说清楚三件事，MigraQ 就能干活

出问题了怎么办

通用行动指南——遇到任何问题都能推进解决

迁移过程中难免遇到操作没成功、结果不符预期、卡住或报错。这里不列具体问题清单，而是告诉你一套通用的正确处理方法：遇到任何问题时，该采取什么动作、怎么和 MigraQ 沟通来推进解决。

💬1把问题「说清楚」，而不是「说情绪」

MigraQ 能记住同一会话的上下文，但看不到你的屏幕。遇到问题时，最有效的做法是一次把三件事说清楚：

  • 你正在做什么（当前处于哪个迁移步骤）
  • 你期望的结果是什么
  • 实际发生了什么（报错信息、异常状态、卡住、结果不符）
✗ 不好的说法迁移失败了，怎么办？
✓ 好的说法我在做 Redis 迁移的第 3 步，DTS 校验任务报了 SrcInstance connect failed，帮我看看是什么原因？
🔑2提供关键信息，不要藏着掖着

同一会话内已确认的信息 MigraQ 会自动继承；但首次提问或开启新会话时，请尽量携带以下定位信息，让它一次就能精准定位：

任务标识迁移任务 ID、校验任务 ID、集群 ID
地域 / 环境源端和目标端的地域（如 ap-shanghai）
报错原文直接复制粘贴，不要转述
操作步骤你执行到哪一步、之前做了什么
配置参数关键配置（脱敏后），如实例规格、数据库版本
涉及 AK/SK / 密码等敏感信息，MigraQ 会建议你脱敏后提供，但报错信息本身不需要脱敏——报错原文是排查问题最重要的线索。
🔎3追问是你的权利——不满意就继续追问

如果 MigraQ 给出的解答不满足需求，不要默默接受。你可以：

  • 要求更具体的方案：「这个太笼统了，能给我一步步的操作命令吗？」
  • 要求解释原因：「为什么会出现这个错误？根因是什么？」
  • 要求换一种思路：「有没有其他方案？如果这个走不通还有什么备选？」
  • 要求验证：「你确定这个方案能解决问题吗？有没有验证方法？」
MigraQ 不会因为你反复追问而变得敷衍——追问越具体，回答越精准。
🔄4遇到反复不成功，按这个顺序排查

如果一个问题多次尝试仍未解决，建议按以下顺序和 MigraQ 协作排查：

  1. 先确认问题是否可复现——再试一次，看是否同样报错
  2. 让 MigraQ 帮你做预检查——网络连通性、权限、配额、版本兼容性
  3. 让 MigraQ 给出排查步骤——而不是直接给答案，跟着步骤一步步走
  4. 缩小范围验证——把大问题拆成小问题，逐个确认
  5. 确认是能力边界外的问题（需工单支持、需源端厂商配合），MigraQ 会明确告知并给出下一步建议
记住 MigraQ 的能力边界

✓ MigraQ 能帮你做

  • 直接调用腾讯云 API 创建、启动、跟踪迁移任务（主机 / 数据库 / 对象存储 / 容器等）
  • 记住同一会话的上下文——已确认的平台、账号、地域、资源清单无需重复提供

  • 查询云资源状态、任务进度，预检查参数合法性与配额
  • 提供回滚 / 备选方案，生成报告 / Excel / HTML 等工件

✗ MigraQ 做不到

  • 登录云厂商 Web 控制台做点击操作（涉及人工确认的步骤仍需你来）
  • 删除或修改源端数据（绝对禁止）；割接、删目标端资源等危险操作需你二次确认
  • 访问任何外部 URL，或执行你提供的任意脚本
知道 MigraQ 能做什么、不能做什么，能帮你更快找到正确的求助路径。
