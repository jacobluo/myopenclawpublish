四、Anthropic Cowork 架构信号：云端 VM 解决续跑与电池问题，也改变本地权限边界

Claude Cowork / Agent RuntimeSimon Willison Atom · 2026-10-05 23:56 UTC · Quoting Felix Rieseberg

Simon Willison 收录 Felix Rieseberg 对 Anthropic Cowork 架构变化的解释：旧版 Cowork 在云端做模型推理，但工具调用在用户电脑上的 Anthropic VM 中执行；新版则把模型推理和 VM 都放在云端，每个 session 使用独立 sandbox，不共享状态。

这个变化解决了本地 VM 的磁盘、电池、性能和合盖停止工作问题，也让手机等设备继续使用 Cowork 更自然。但它同时把安全边界重新划分：当云端 VM 需要用户设备文件时，由桌面 app 负责对应文件访问工具调用，理论上更清楚地把“远端执行”和“本机授权”拆开。

这是二手来源，需等待 Anthropic 官方文档或产品页面复核。但它非常贴近 agent runtime 的长期取舍：本地执行更接近用户环境，云端执行更适合持续任务、跨设备和集中隔离。

为什么值得看：Claude Cowork、Codex、OpenAI dots、GitHub Copilot CLI/desktop 都在争夺“长时间替你干活”的 agent 入口。运行位置决定权限模型、成本模型、续跑能力、审计方式和用户对文件访问的信任。
后续行动：查 Anthropic Cowork 官方帮助页，确认云端 VM 的数据保留、网络访问、文件授权、session 隔离和企业管理策略；对比 Codex remote、GitHub Copilot coding agent、OpenAI dots 的 runtime 边界。

Platform StrategyOpenAI News RSS · 2026-10-05 · OpenAI News RSS

为什么值得看：这条归纳帮助理解 OpenAI 的产品路线：不是只发模型，而是在围绕模型输出建立可监管、可商业化、可审计的生态。对投资、创业和产品设计都有参考价值。
