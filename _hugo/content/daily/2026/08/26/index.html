一、全栈 AI 竞争：从“更强模型”转向“更便宜、更快、更可控地完成工作”

AI InfrastructureOpenAI / Sarah Friar · 2026-08-25 07:05 UTC · The full stack behind abundant intelligence

OpenAI 把算力策略描述成一个覆盖数据中心、芯片、frontier models、developer platform、消费/企业产品和 AI-native devices 的一体化系统。文章强调不同工作负载需要不同的芯片、软件、网络、电力和延迟组合，OpenAI 会同时使用 Microsoft、NVIDIA、AWS、AMD、Broadcom、Cerebras、CoreWeave、Oracle、SB Energy、SoftBank 等伙伴，同时保留自研路径。

最值得注意的是指标口径：文章反复强调 useful intelligence per dollar，而不是单纯看峰值算力或模型榜单。它还把 GPT-5.6 Sol 在 coding agent index 上用更少输出 token 达到新高的例子放进经济性叙事里，说明模型、路由、上下文管理和硬件效率会共同决定 agent 能否进入更多真实任务。

为什么值得看：Follow List 里 OpenAI、Codex、agent workflow 是主线。今天这条把“模型能力”接到“单位成本完成有效工作”的商业指标上，对 WorkBuddy、OpenClaw 和 AI 产业链研究都更可操作。
后续行动：把 AI 基础设施跟踪指标从 capex/芯片型号扩展到 latency、tokens per successful task、routing efficiency、agent retry rate 和 gross margin pressure。

二、Jalapeño：OpenAI 首个自研推理芯片给出实测结果

Inference / SiliconOpenAI · 2026-08-25 07:00 UTC · Jalapeño’s first results show industry-leading speed and efficiency in AI inference

OpenAI 公布 Jalapeño 的首批测试结果，称其在 InferenceX 公共 benchmark 上覆盖 GPT-OSS 120B、DeepSeek R1 670B、Kimi K2.5 1T 等模型，展现更高每瓦吞吐和更低端到端延迟。文章给出的总体区间是：在三类模型上，峰值吞吐下每瓦 AI work 提升约 1.5 到 1.9 倍，端到端延迟降低约 1.7 到 3.6 倍；高交互工作负载下性能提升约 2.1 到 4.1 倍。

它特别把目标对准 interactive agents：agent 多步串行执行时，单步延迟会累积成任务级失败和成本。OpenAI 还称用 Codex 和 GPT-Astra 在两个月内把三个原本不在生产计划里的开放权重模型优化到高性能，并且部分 GPT-OSS attention/MoE block 的 AI 生成实现比原有人写版本快 1.5 到 1.8 倍。

为什么值得看：这条直接影响 AI 产业链与推理成本判断。若自研推理芯片真正进入规模部署，OpenAI 的议价、模型服务成本、agent 产品响应速度和供应链组合都会改变。
后续行动：跟踪 Jalapeño 年底部署进展、与 NVIDIA/AMD/Cerebras 的互补关系、InferenceX 复测结果，以及 OpenAI 是否把低延迟能力转化为新的 agent SKU。

五、Granite 4.2：开源 reasoning 模型把 tool calling 和 agentic RL 放进主叙事

Open Models / AgentsIBM Granite / Hugging Face · 2026-08-25 15:14 UTC · Granite 4.2 LLMs: How They're Built

IBM Granite 团队发布 Granite 4.2 技术 walkthrough：3B、8B、30B dense decoder-only reasoning 模型，从头预训练约 15T tokens，context 扩到 512K，SFT 数据包含 chain-of-thought、reasoning 和 agentic trajectory，再通过多阶段 RL 后训练。8B 和 30B 还加入 agentic RL，在真实沙箱环境中学习使用工具。

产品能力上，它强调 thinking/non-thinking switch、low-effort thinking mode、native tool calling，并给出 Transformers、tool calling、多轮工具响应、agentic coding harnesses 等使用方式。开放模型已经把“能不能接工具、能不能进 coding harness、能不能控制推理预算”放到了发布核心。

为什么值得看：Follow List 的 Nathan Lambert、Hugging Face、Jim Fan、Francois Chollet 等线索都关注开放模型是否能进入真实工作流。Granite 4.2 是企业友好开源模型向 agentic deployment 靠拢的清晰样本。
后续行动：记录 Granite 4.2 的 license、tool calling 格式、long-context 成本和本地推理门槛；后续可用一个固定 agent/coding/eval harness 与 GPT-OSS、Qwen、Kimi 开源模型横向比较。

六、Gradio Workflow 与 Quantization-Aware Healing：落地工程的两块拼图

Workflow UI / DeploymentHugging Face / Gradio · 2026-08-25 00:00 UTC · Wire It, Run It, Deploy It: AI Workflows in Gradio

Gradio 发布 gr.Workflow，核心是把多步 AI pipeline 描述成 typed nodes graph，并直接生成可运行的拖拽画布、可见中间结果、REST API 和一键部署到 Hugging Face Spaces。示例包括图片编辑、并行图像生成、背景移除、voiceover、dataset profiling 和 GPU 模型节点。

这类工具降低了 AI 应用从 notebook/脚本走向可分享界面的门槛，尤其适合演示、内部工具和小团队快速验证。它和 LangGraph、OpenClaw canvas、Copilot canvases 的共同方向是：AI workflow 需要可视化、可运行、可调试，而不是藏在一段脚本里。

为什么值得看：对 WorkBuddy 来说，很多客户场景先需要“能看懂流程、能改节点、能复现结果”的交付物。Gradio Workflow 是一个可借鉴的轻量形态。
后续行动：评估 Gradio Workflow 是否适合做客户 PoC 的 pipeline 展示层，尤其是多模型、多媒体、数据处理和人工审阅节点。
Model EfficiencyMultiverse Computing / Hugging Face · 2026-08-25 11:39 UTC · Quantization-Aware Healing

Multiverse Computing 介绍 Quantization-Aware Healing，目标是在模型已经结构压缩并量化到 4-bit 之后恢复能力。文章称，他们把 GPT-OSS 120B 压缩到 60B 并量化到 MXFP4 后，通过 QAH 让 4-bit 模型在 9 个 benchmark 中 7 个超过其 full-precision 版本。

这条需要谨慎看待：它是团队博客和论文口径，仍需独立复现。但方向重要，因为实际部署里模型经常先被压缩再量化，传统 healing 或 QAT 不一定适配这种“压缩 + 量化”组合。

为什么值得看：推理成本是 agent 扩张的硬约束。若压缩模型能在特定任务上恢复甚至超过原 checkpoint，就会影响本地部署、边缘部署和企业私有化方案。
后续行动：把 QAH 放入开放模型部署观察清单，重点看复现实验、模型卡、训练成本、真实任务表现和是否只对特定 benchmark 有效。
